Use English for repository documentation, source comments, test names, and commit messages. Keep non-English text only where it is needed as Unicode or localization test data.

## Neovim-style interaction and UI

- Design Radian as a command-first, keyboard-driven workbench inspired by Neovim. This applies to actions, workflows, popups and visual presentation, not only navigation keys. Do not merely add Vim motions to a mouse-oriented UI.
- Make app-owned actions available as named, configurable commands in the shared keymap. Prefer mnemonic context-local keys and leader-prefixed global commands. Reuse familiar Neovim motions and key sequences when their meaning fits; do not invent shortcuts independently in each widget. Mouse interaction may supplement commands, not replace them.
- Prefer compact panes, searchable lists, text status lines and transient previews over desktop-style dialog chrome and toolbars. Make focus, selection, scope and pending state visible without adding redundant controls.
- Keep app-owned popups content-only, without dedicated popup title/header rows or frame-border titles. Input-field borders may carry short picker or prompt titles. Preserve meaningful headings inside the actual content. Do not add top-right `×` close controls or bottom action-button rows such as Apply, Cancel, Close, Copy or Continue. Invoke those actions through commands. In-content choices such as model effort levels and filter tabs may remain when they communicate editable state.
- Use `UI_BORDER_STYLE` from `src/ui/border-style.ts` for app-owned enclosing borders, including input fields, dialogs, notification cards and transcript focus outlines. Keep borderless surfaces borderless; internal pane separators, tree guides and data-table grids retain their own straight-line rendering.
- When removing a button, preserve necessary behavior through an explicit command. Remove redundant convenience actions rather than adding commands solely to preserve every existing button.
- Keep interactions predictable across surfaces: browsing previews does not commit changes, Enter explicitly activates or submits where appropriate, and Esc backs out or cancels unsubmitted choices. Closing a surface must not imply rollback of an already accepted action.
- Search-and-list popups use a borderless outer surface and a rounded search field with a centered title, a `>` prompt and matched/total counts. Search fields have no placeholder. Popup input fields and their native editors share the popup background in both focus states. Lists have one cell of horizontal padding on each side, with no blank row below search. Use the shared `POPUP_SIZES` presets in `src/ui/popup-layout.ts`: `compact` for short input/confirmation dialogs, `standard` for single-list pickers, and `expanded` for preview/detail surfaces, and `large` for History and searchable Git Changes. Keep search/list sizes independent of query and result counts; preserve preview panes and state controls. Input-only Ask popups keep the compact preset width and height limit, but fit the input field's actual height without outer padding. Count selectable candidates, not group headings, and hide unknown counts during loading or discovery failures.
- Opening a searchable popup starts an empty query with the input caret at the beginning and focuses search. Keep search in Tab/Shift+Tab traversal and provide `/` to return from results. Discovery, refresh and resize preserve the current query, input caret, focus and candidate identity when it still exists; apply incoming data to the latest query, not a request-time copy. Changing an account/authentication stage may start a fresh search or focus its ordinary/secret input.
- Preview commands focus the revealed body and return to search when toggled back. Compact Tab traversal includes search, results and previews, revealing the target region before focusing it.
- The session monitor remains list-only, without a preview pane. History previews reuse the complete AgentPanel renderer, including tabs, composer, run state, pending messages, subagents and telemetry. Do not add preview-specific labels, abbreviated transcript renderers or alternate compact layouts. Keep preview scrolling available, but disable editing, tab actions, folding, link activation and persistence. Put session-browsing loading feedback inside the session list, not on the popup frame or in a separate preview loading surface.
- Derive help and contextual hints from the actual configured keymap and use Neovim-style notation such as `<leader>`, `<C-x>`, `<CR>` and `<Esc>`. Keep routine default navigation hints in full Help rather than cluttering the footer; retain relevant app-specific actions and user overrides.
- Neovim-inspired does not mean forcing modal editing into every input. Preserve literal text entry, explicit user overrides, and native input ownership in embedded editors and terminals. Follow the detailed input and navigation rules below.

## UI feedback

- Use `LoadingSpinner` from `src/ui/loading-spinner.ts` for loading indicators across the UI. It keeps the animation visible for at least 500 ms without delaying results or errors. Call `cancel()` when the owning screen is hidden; destroying its renderable also clears its timers.
- Popups use `attachPopupActivity` from `src/ui/popup-layout.ts` for loading placement. Center the spinner and loading message in the relevant body only while no data is available. Preserve existing content during refresh and use a small in-body indicator; anchor detail/action activity beside the selected candidate when available. Never put activity on popup frames or reserve spinner-only header rows. Ready data and errors replace loading messages immediately, including during the spinner's minimum-visible tail. Prepared caches must open without starting a loading indicator.

## Keyboard input and navigation

- Arrow keys and `Ctrl+N/P` are required defaults throughout app-owned navigable UI. `Ctrl+N` moves down/next and `Ctrl+P` moves up/previous as appropriate to the surface. Keep both input styles available; `Ctrl+N/P` is not merely a fallback when Vim keys are unavailable.
- Additionally support the applicable `h/j/k/l` navigation keys wherever practical. Do not force them where they conflict with text input, existing key semantics or native input ownership.
- In scrollable or paged views, provide jump navigation such as `Ctrl+D/U` for half-page down/up wherever practical. In candidate lists, jump the candidate cursor by half a viewport of items; in read-only bodies, scroll the focused body. From a search input, `Ctrl+D/U` must preserve the query and caret, move focus to the results list and perform the candidate jump from the current selection. Further presses and held-key repeats continue list navigation; do not replay the same event as native editing after focus changes. In compact layouts, reveal the results list before handing off focus. `Ctrl+C` alone clears the search query, consistent with Agent draft clearing; do not bind `Ctrl+L` as an alias. An empty query makes this a no-op: do not close the popup, detach the app, interrupt work or clear the Agent draft. Consume held clear-key repeats until release even if focus changes. Ordinary prompts and native PTYs retain their own editing behavior.
- Searchable lists must support `Ctrl+N/P` in both search-input and results-list focus; offer `j/k` in results lists where practical. These keys move the candidate cursor one item at a time, not the raw scroll position. Keep the candidate visibly highlighted even while search retains input focus; adjust the viewport only as needed to reveal an off-screen candidate. Do not let navigation disappear when focus moves within a popup.
- Tab strips support Left/Right and `Ctrl+N/P` in their own focus context, with `h/l` where practical. Keep repeated navigation within the strip instead of moving focus into its content after one key.
- Active completion menus support Up/Down and `Ctrl+N/P`; after dismissal, restore ordinary input editing.
- Keep unmodified `h/j/k/l` literal in text inputs and preserve native input ownership in embedded editors and terminals. Respect explicit user keybinding overrides.
- Omit bare arrow-key navigation from shortcut hints and help; show the actual configured alternative keys instead. Modified arrow keys and multi-key sequences remain meaningful shortcuts.
- Cover navigation across search/results focus, text-input preservation and shortcut hints with regression tests when changing these surfaces.

## Error handling

- Return `Result<T, E>` with custom error types and stable codes for expected domain, I/O, cancellation and protocol failures. Callers must explicitly handle both branches.
- Keep unexpected programming errors as exceptions with their original cause and stack; log them at host/UI boundaries, not as ordinary input errors.
- Limit `try/catch` to exception-based SDK/OS boundaries and cleanup. Do not classify errors by message text or silently turn all failures into empty values.
- Distinguish an accepted action with a persistence warning from a rejected action. A timeout does not prove cancellation or rollback.
- Convert a failed Result to rejection only at boundaries whose contract requires exceptions (for example Pi SDK tool execution).
